# Contributing

Useful contributions improve real repair outcomes: a missed defect, an unnecessary rewrite, a false success claim, or clearer tool fallback behavior.

For an issue, include the user request, a minimal project or reproduction steps, available tools, expected behavior, and actual behavior. Remove secrets and personal data.

For a change, explain the observed failure it addresses and try the revised skill against that case. Preserve audit-only requests and existing product scope. Do not add mandatory tools without a demonstrated need.

The behavioral scenarios in [docs/evaluation.md](docs/evaluation.md) are a starting point for manual evaluation, not a claim of completed testing.
